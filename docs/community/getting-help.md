# Getting help

We are happy to help in the
[DynaPlex GitHub repository](https://github.com/DynaPlex/DynaPlex):

- **Questions and discussion** — please use
  [GitHub Discussions](https://github.com/DynaPlex/DynaPlex/discussions).
- **Bug reports and feature requests** — please open a
  [GitHub issue](https://github.com/DynaPlex/DynaPlex/issues).

When you find a bug, please include a short, self-contained script that
reproduces the problem, and indicate the Python version, the DynaPlex version,
the platform (Windows, Linux, macOS), and — if relevant — the version of
PyTorch. The output of `python -m dynaplex.selftest` is often helpful too.

## Feature requests

DynaPlex and the DynaML modelling language are in rapid development, and the
language grows based on what modellers actually need. If you genuinely miss
something for applications in supply chain, logistics, transportation,
maintenance optimization, or similar fields, please open a feature request
as a [GitHub issue](https://github.com/DynaPlex/DynaPlex/issues). The most
useful requests explain three things:

1. what you are trying to achieve in your MDP;
2. why that is difficult with the current DynaML limitations;
3. your proposed addition to DynaML.

## Contributing to the documentation

The source of this documentation lives in the
[public repository](https://github.com/DynaPlex/DynaPlex). Corrections and
clarifications are welcome — every page has an edit button that takes you to
the corresponding file on GitHub, where you can propose a change directly.
